# Architecture - the module map

Split out of [ARCHITECTURE.md](../ARCHITECTURE.md). One row per file: what it owns, in plain
language, present tense. The terse version every session carries is in
[CLAUDE.md](../../CLAUDE.md)'s own module map; this is the one read on demand.

| File | What it does |
|------|--------------|
| `index.html` | The entry point and page markup, and nothing else. The JavaScript here is just wiring: grab the canvases, start PixiJS, call each module's `init`, connect the lifecycle events. The styling is nine `<link>` tags. It was once a ~2400-line script plus a ~1370-line stylesheet, and a guard hook keeps either from creeping back. |
| `src/css/*.css` | All of the app's styling, split by the part of the screen it dresses: `base.css` (page reset, the floating-panel surface every control shares, canvas layers, player mode), then `controlPanel.css`, `toolbar.css`, `roomCard.css`, `playerPane.css`, `legend.css`, `sceneManager.css`, `about.css`, `combat.css`, `dock.css`, `notesPanel.css`, `worldMap.css`, `overlays.css`. They load in that order and it matters, because CSS is one shared cascade. |
| `renderer.js` | The PixiJS/WebGL wrapper: the drawing context, the layers everything else hangs off, the map sprite and the texture pool behind it. Each fog pass has its own file beside this one. |
| `playerFogPass.js` | The Player's fog drawn as one pass over the whole window, shaders and all. Covering the window rather than the map is what leaves no edge for a seam to sit on. |
| `dmFogLayer.js` | The DM's fog, which is a different thing entirely: map-sized sprites, the crossfade between the fog before an edit and after it, and the drifting cloud texture masked to wherever fog is opaque. |
| `render.js` | The render loop. Each frame it decides which layers actually changed and redraws only those, keeps the canvases sized to the window, and paints the cursor and polygon-selection overlay. |
| `state.js` | Shared values that several files need. Loaded first so they exist before anything reads them. |
| `fog.js` | The fog itself: the canvases that store what is hidden, the blur pipeline that softens them, and the reveal/hide logic. |
| `fogAnim.js` | Four loops, each ticking against the clock: clouds drifting and morphing, a reveal or shroud fading in, the fog closing over a scene switch and opening again, and the fog colour easing from one scene's to the next. A loop that stalls shows the players a frozen picture, so each one owns its own frame handle and can be stopped on its own. |
| `fogClouds.js` | The soft moving texture that stops the fog reading as a flat fill. One window builds the sixteen frames and every other window copies them, because building four sets at once freezes all of them for seconds. |
| `fogControls.js` | The fog's controls behind Scene control and Settings: the animation presets and their dials, and the colour, feather, half-shroud and door-size inputs. Feather and Half are remembered between sittings. It reads and writes fog settings; it draws nothing. |
| `fogGeometry.js` | The pure fog math: polygon insetting, rounded paths, cone vertices, tint-colour derivation, animation timing. Plain functions in, values out, no drawing. Unit-tested. |
| `fogColor.js` | The colour arithmetic behind the fog: one picked colour into the solid fill and the tint that glows over it, the halfway step between two of them for a scene change, and the look settings a saved scene carries. Plain functions in, values out. Unit-tested. |
| `doorGeometry.js` | The pure door math: notch placement and corners, cell snapping, which wall a point is near, door placement from a floor plan, shared-wall detection, and the remap that keeps a door on its map point when the outline changes. Unit-tested. |
| `shapeDetail.js` | Carries a room's per-vertex and per-wall detail across a repair: it flattens each curve for the clipping library, then rebuilds the surviving stretches as exact cubics and puts each corner radius and each door back on the wall that now holds it. Unit-tested. |
| `lightGeometry.js` | Reads a floor plan's lights into map pixels, and works out the polygon each starts as: its room, clipped by its radius, or a circle when no room holds it. Pure geometry, unit-tested. |
| `vttPlan.js` | Turns a Universal VTT floor plan's wall segments into room polygons, and reports where its openings sit. Pure geometry, no dependencies, unit-tested. |
| `roomOps.js` | Reshapes rooms already on the map: joins the ones a drawn shape overlaps into one, trims a drawn shape out of them, and cuts one room into two along a clicked path. Wraps the vendored `polygon-clipping` library and answers with vertex lists or a refusal reason, never a throw. Unit-tested. |
| `floorPlan.js` | The app side of that: finding the plan beside the map, the offer notice, setting Grid Size from the plan at import, and drawing the rooms and their doorways. |
| `tools.js` | Which tool the DM is holding, the state every tool shares, and the table a click is dispatched through. Each tool is a row in that table and a file of its own, so a new one is added without touching the others. The cone is drawn apex-first - press at the point of origin, drag towards where it points - and commits as an ordinary polygon with a shallow arc on its far edge, so nothing downstream knows a cone from any other shape. |
| `shapeCommit.js` | What happens to a shape once it is drawn: it becomes a room, an effect, or a repair of one already there. Join, Trim and Cut all end here, and so does every refusal the DM sees. |
| `toolPoly.js` | The Polygon tool: one vertex per click, closing either by clicking the first vertex again or by crossing its own line. |
| `presetGeometry.js` | The pure preset math: the sizes each shape offers in feet, the outline a size makes at the grid's scale, the cursor label, and the wrap-around step through a size list. Unit-tested. |
| `toolPreset.js` | Effect presets: the size row above the bar, the outline and label that follow the cursor, the wheel that steps sizes, and placing one with a click or an aiming drag. |
| `toolShapes.js` | The three tools drawn by dragging: rectangle, circle and cone. Each starts on the press and commits what it has on release. |
| `toolBrush.js` | The fog brush. Strokes queue while the pointer moves and land in one pass, so painting stays smooth on a big map. |
| `toolDoor.js` | The Door tool: which wall a click belongs to, where along it the door sits, and the notch that opens in the fog there. |
| `toolCut.js` | The Cut tool: a free path drawn across a shape, and the two pieces it leaves. |
| `shapeMarkers.js` | Draws one corner (square at object level, circle in edit mode, an optional coloured ring or stroke) and one hole's hatch fill. Read by shapeSelect.js, shapeBox.js and toolPreview.js alike, so it belongs to none of them. |
| `toolPreview.js` | The outline a tool shows while the DM is still drawing, before anything is committed. |
| `shapeHit.js` | What the cursor is over: whether a point is inside a room, how far it is from a wall, and where along that wall it lands. A bent wall is measured against its curve. Pure. |
| `shapeSelect.js` | The Select tool: what is picked, and every edit made by hand on the map. It holds the levels the way Figma does - one click picks a shape as a whole object and draws its bounding box, a double-click enters edit mode and puts its vertices, walls and holes in reach, and a Ctrl+click on a shape not yet open does the same in one press. A hole is picked by clicking its empty middle, takes a box of its own, and opens its corners on one more double-click; Escape climbs back one level per press. Only the live level answers the mouse. A hole moves as one ring and stops where it would leave its room. Also draws every room and effect: a wash carrying its fog state, a soft inner edge, and a line that goes gold when held and white while editing. |
| `openLine.js` | What the room editor draws for a picked road: an open line has no fill and no closing wall, so its chrome is the line gone gold and, in edit mode, its corners and the selected corner's curve handles. The handle markers are shared with `drawPolyOutline`. |
| `cornerGeometry.js` | The pure corner-rounding math: where a corner's rounding circle sits, which way a drag along it grows the radius, and how far each corner can round. Unit-tested. |
| `cornerRound.js` | The rounding circles on a picked shape's corners, the drag that rounds one corner or all of them, its label, and the number field a double-click opens beside a circle. |
| `shapeBox.js` | The bounding box a picked shape wears, and the rotate and scale its four corner handles drive. A corner scales against the opposite corner; the ring just outside it rotates around the box centre. Shift holds proportion and snaps rotation to 15 degrees. A picked hole gets the same box, and stops where it would leave its room. |
| `shapeClipboard.js` | Copy, cut, paste and duplicate for rooms, effects and holes, on Figma's Ctrl+C, Ctrl+X, Ctrl+V and Ctrl+D, and the copy an Alt+drag moves. Cut is a copy and a delete, one undo step; an Alt+drag makes its copy on the drag's first movement and spends only the drag's own undo step. A paste centres the shape on the pointer and a duplicate lands one grid square across. The copy keeps its name, its description and its fog state. The clipboard outlives a scene switch and remembers which list it came from, so an effect pasted in Rooms mode still lands among the effects. A copied hole pastes as a hole into whichever shape sits under the pointer. |
| `input.js` | The DM's mouse and keyboard: painting with the tools, keyboard shortcuts, the legend toggle. Files dropped on the window are `dragDrop.js`'s. |
| `undo.js` | Undo/redo history for fog edits. |
| `effects.js` | Map effects - burning ground, and the materials to come. Each is a polygon carrying a material name, drawn under the fog on both screens as a flaming border: the outline burns inward with dissolving tongues over a faint fill, with sparks, smoke and haze. Rendered by a fragment shader over the polygon's own distance field, in two PixiJS meshes per effect. Owns the `effects` array's model and the meshes that draw it; the passes themselves are `effectShader.js`'s and their colours `effectMaterials.js`'s. The look is a fixed set of numbers in the module with no UI over it. (The ember relight of the map grid inside a zone lives in `grid.js`.) |
| `effectMaterials.js` | What an effect is made of. A record per material carries the colours its fire burns through, how warm the hottest part reads, and the swatch the picker shows. A new material is a record here and nothing else. |
| `effectShader.js` | The two passes an effect is drawn with: one that adds light - flames, interior glow, sparks - and one over it that takes light away, for smoke and haze. Every colour arrives from the material. |
| `grid.js` | The grid overlay: squares or hexes, size/offset/colour, and line width that scales with zoom. Also the one place a grid change is committed from - redraw, push to the Player, save onto the scene - and what grid a freshly imported map starts with. Relights the grid in ember inside each effect zone (`drawEffectGridGlow`), because the map grid draws on a canvas above the effect layer. |
| `gridCalibrate.js` | Fitting the grid to a map that already has one drawn on it, without typing numbers. Armed from the Fit icon in Scene control, which puts the dock's pane away so the map is clear; leaving hands it back. **The DM drags the shape the grid is made of.** For a square grid that is a box from one intersection in the map art to another several cells away, forced square because a cell is, which makes the two axes one measurement and lets a map showing only its vertical lines be enough. For a hex grid it is one big hex dragged from a corner to the opposite corner, snapped to one of the six corner directions because corners are what the map art draws, with the grid's hexes drawn inside it. Its diagonal crosses n hexes, each twice the circumradius with a shared wall of one between neighbours, so it is (3n - 1) circumradii; an odd n centres the big hex on a cell and lands all six corners on the grid, and an even one lands only the two corners pressed. The DM's grid is hidden for the length of the gesture, and the square and the big hex each draw their own cells. The cell count is guessed from the size already set and corrected with a stepper floating beside the shape, so the cell is the drag divided by what that count spans; the stepper sits clear of the magnifier; a drag too small to fit one cell is refused rather than clamped. Once drawn the shape stays live: drag its middle to slide the phase with the cell size held, or its far handle to resize with the count held. Past the box, a square grid also offers a handle on any intersection that re-solves the cell size by least squares so the grid lands there, which takes out the error a short measurement multiplies over a long map. A magnifier shows the map at four times the on-screen scale, and an animated map is held on one frame for the length of the gesture. Owlbear Rodeo, Roll20 and Foundry all size from a fixed multi-cell square and then correct at a distance; this is that shape with a count the DM can raise. |
| `scenes.js` | Auto-save loop, fog-load helpers, and the error-recovery path above the database layer. |
| `sceneDelete.js` | Deleting a scene, and taking it back. The list loses the scene at once, but the database keeps it until the undo toast runs out, so the DM can undo a mistake mid-session. Deleting the scene on screen also empties the app and moves it to another one. |
| `sceneList.js` | The list of scenes the app holds, whatever shows it: loaded at startup with the last scene reopened, its thumbnails kept in step, the open scene's name in the dock, and the counter that drops a stale scene switch. The Scene library and the world map both read it. |
| `mapImport.js` | Turning files the DM picks or drops into scenes: which kinds are accepted, how a whole selection is taken in one at a time, how a second import waits for the first to finish, and where an animated map is written. Problems are collected and reported once at the end, so a long import never waits on a click. |
| `sceneSwitch.js` | `switchScene`: the fog closing over the outgoing map, the store read, the decode, and the fog reopening on the new one. Every path into a loaded map goes through it. |
| `sceneGroups.js` | Groups in the scene library. A group is a name a scene carries, so the scene's own `group` field is the only record of what is filed where; this file keeps the order the headings appear in, which ones are collapsed, and a heading made before anything was dragged into it. |
| `sceneStore.js` | Saving and loading scenes to the browser's local database (IndexedDB). Changing one field of a scene the app is not currently showing goes through `updateScene`, which reads and writes in one transaction so an autosave cannot land between the two and lose a fog reveal. |
| `mapLoader.js` | Loading a map image into the app and driving the progress bar, including the batch label a multi-map import puts on it. Shared by scene-switching and backup restore. |
| `mapConvert.js` | Asking whether to shrink an oversized animated map at import, and re-encoding it if the answer is yes. Pure box-fitting maths plus the recorder that drives it. |
| `viewport.js` | Pan, zoom, fitting a map to the screen, and the camera arithmetic every push to the Player carries. |
| `mapTurn.js` | My seat: the DM's map turned 0°, 90°, 180° or 270° so the laptop faces the way the table does from the DM's chair. Every canvas over the map turns together, so nothing drawn can slide off the map; the few places that meet a mouse position or place a panel convert through here. The TV never sees it. |
| `ping.js` | The ping: a gold ring with ticks, ripples and sparks at a map point for about two and a half seconds, drawn in the DM window and on the TV alike. It is sized to the window rather than the map and stored nowhere. |
| `lights.js` | A scene's lights, which are polygons in a list of their own. It seeds them from the floor plan on request, draws a faint warm line round the lit areas under the fog on both screens, and sends the outlines to the Player. |
| `playerWindow.js` | The DM's side of the Player window: opening it, keeping a warm one ready so the next press is instant, and deciding what is sent to it and when. |
| `minimap.js` | The DM's live preview of the Player camera in the bottom-left corner, and the remote control that drives it. |
| `stageWindow.js` | The DM side of the Player screen while two maps are up: opening that window, keeping a warm one ready so the next press is instant, wiring each column to its own half, and closing it. |
| `paneRuntime.js` | The other end of every command the DM shell sends a column. Each message presses the control that column already has, so a column behaves like the DM window it is, and no behaviour is written twice. |
| `panes.js` | Two-column mode, where the DM window's map area splits in two and each half holds a whole second copy of the app running in an `<iframe>` with its chrome hidden. Owns the two frames, which column is selected, the draggable divider, and every command the DM's chrome sends into a column. A column therefore has its own scene, camera, grid, rooms, fog, undo history and Player window with nothing written for it. Also the small piece that runs INSIDE a column: Electron gives a subframe no bridge to the shell, so the column borrows the parent window's. |
| `twoMaps.js` | The Two maps toggle in the dock: into two columns from the open map, and back to one. |
| `stage.js` | The Player window in two-map mode. One window, split where the DM's divider sits, holding a whole Player in each half and painting the chasm between them - a dark band with each floor's fog colour bleeding in, embers drifting up it and a faint seam of light down its centre. One window rather than two because Windows gives one fullscreen window per display, so a pair could never both be fullscreen on the same TV. |
| `video.js` | Animated (video) map support: file loading, DOM compositing, decoding, the frame loop, the freeze watchdog. |
| `videoDiag.js` | A panel that shows how an animated map is actually playing, plus the log file it writes. The counting runs whether or not the panel is open, so a stutter the DM only hears about later is still on record. |
| `display.js` | Detecting the Player screen's real size so the fog and map render at the right resolution. |
| `backup.js` | The export/restore-to-zip feature. |
| `dragDrop.js` | What happens when files are dropped on the DM window. A floor plan arriving alone is attached to whatever scene is open, which is the case where it got separated from the map it belongs to. A dropped map imports nothing; maps come in through the + button. |
| `toolbar.js` | DM-only UI control wiring: toolbar buttons, sliders, the scene dropdown, Player controls. The Fog tab's own controls live in `fogControls.js`. Also the Rooms/Effects switch, the Merge and Cut out repairs, the material picker, and which tools each mode puts on the bar. The strip above the toolbar changes with both - `input.js`'s `updateContextPanels` owns every visibility decision in it. |
| `shapeMenu.js` | The bar's two lists. The shape button wears whichever shape the current mode last drew with, and the operations button wears the repair last picked: Merge, Cut out or Split. A chevron beside each, or a right-click on the button, opens its list, with a check on the current pick and a shape the mode lacks greyed. |
| `colorPicker.js` | The fog colour control: a saturation square, a hue strip and a hex field, kept in step with each other. It writes into the same hidden colour input the rest of the app listens to. |
| `dock.js` | The dock on the right edge of the DM screen: an icon rail and one pane beside it, over the map. A rail tab opens its pane and the open tab's second click shuts it; the window tabs open the scene library, the Bestiary, the fight table and the shortcuts. The open pane and the width the DM dragged it to are remembered, and the width gives way so the toolbar, which stays centred on the window, stays clear. |
| `roomLink.js` | Two-map mode's room. A column has no dock, so it reports its selected room and its scene's name and notes to the DM window: the room's name, notes, fog, corner radius and pictures. The left panel shows the selected column's room, and every edit made there goes back to that column alone, which refuses it if its selection has moved on. |
| `controlPanel.js` | The dock's Scene control pane: Fog, Rooms, Grid, Player and My seat. A presentational layer over the older hidden controls: colour fields that open their picker beside the dock, the movement dropdown, the eyes, and number fields scrubbed by dragging their icon. |
| `notesPlan.js` | The notes rules that need no screen: the breadcrumb list, a notes string cleaned and capped, and a restored campaign note merged in beside the one the DM has. Unit-tested. |
| `notesPanel.js` | The left panel: breadcrumbs over the notes of the campaign, a place, the scene or the room. The campaign and scene notes are its own field; the room's field and pictures sit inside it but keep their logic in `roomCard.js` and `roomPictures.js`. |
| `worldMapPlan.js` | The world map's rules that need no screen: where scenes start, polygon geometry and which polygon holds a card, and the camera. Unit-tested. |
| `worldRoadPlan.js` | The roads' rules that need no screen: a road cleaned and parsed, its line sampled and measured, an end laid on its scene or place, and what deleting, renaming and restoring do to a road. Unit-tested. |
| `worldMapStore.js` | Where a scene sits on the world map, which place it belongs to and its name, written in one place: the open scene, the store and a column all take the same change. |
| `worldMist.js` | The mist over the world map: a veil and two drifting wisp textures that thin inside the places, with the backdrop's own colour returning there. One svg, built once; a redraw swaps only the place shapes in its masks. |
| `worldBackground.js` | The world map's backdrop: one image chosen in Settings, behind the places, with its place, size and opacity. Its picture sits in a database of its own; the TV never sees it. |
| `worldMap.js` | The world map: a dark layer over the map with places and scenes on it. Zoomed out the places show their names over the scenes' prints; zoomed in the scenes show theirs. It owns the camera, opening and closing, and the keys it keeps from the scene underneath. |
| `worldFindPlan.js` | The Find rules that need no screen: which places, scenes and roads a query matches, how well, and where in the name. Unit-tested. |
| `worldMapFind.js` | Find on the world map: a field above the toolbar with a list under what is typed, grouped Places, Scenes and Roads, with a count. Arrow keys walk it, Enter or a click flies to the row and picks it, Esc closes. |
| `worldMapColumns.js` | Two maps on the world map: a Left and a Right chip at the top, the active one blue and each naming the scene its column holds. A double-click on a scene fills the active column and closes the map; a scene a column holds wears an L or R. Esc, M and the button close the map and leave both columns alone. |
| `worldPickPlan.js` | The multi-pick's rules that need no screen: a Shift-click toggled, which scenes a Shift-dragged box touches, and which places, roads and notes a backup of only the picked scenes carries. Unit-tested. |
| `worldMapPick.js` | More than one scene picked on the world map: a Shift-click toggles a scene, and a Shift-drag on the ground draws a box that adds what it touches. The pick moves together and has its own menu. |
| `worldBackup.js` | Export and Restore in Settings' World map section. Export saves the scenes picked on the map, or everything when none is picked; Restore takes a .zip from a picker or one dropped on the world map. |
| `worldMapEdit.js` | What the DM does on the world map: pick, drag a scene or a place, drop onto a loose scene to make a place, rename in place, find, and add a scene without opening it. |
| `worldPlaces.js` | The places of the world map: room-shaped records (corners, rounding, curves) kept by name, with undo. A scene belongs to the place whose outline holds all of its card, and one pixel outside takes it out. A group with no place gets the rectangle that fits its scenes. |
| `worldRoads.js` | The roads of the world map: open-line records the room editing code edits like a wall, kept by a stored id, with undo. Each end sticks to a scene or a place and follows it; a road holds its own list of scenes, so no scene record gains a field. |
| `worldMapShapes.js` | Drawing a place with the toolbar's own tools, and Merge, Cut out and Split on places. Editing one afterwards is the room's own code, run on the world's camera. |
| `worldMapRoads.js` | Roads in the world map's layer: the dashed line on its casing, its name plate, the Road tool, and deleting. Editing a picked road is the room's own code on an `open` record. |
| `worldMapMenu.js` | The world map's right-click menu: open, rename, take out of its place or delete a scene; rename, fit or delete a place; add a scene or show everything from the ground. |
| `roomPanel.js` | The names drawn on the DM's map over each room, and the arithmetic that finds a spot inside the shape where a name fits. |
| `roomCard.js` | The selected room's name and notes in the left panel, committed as they are typed. It follows the selection alone. |
| `picturePlan.js` | The rules for room pictures that need no screen: how big a picture may be, how the list reorders, and the file name a picture takes inside a backup. |
| `pictureDecode.js` | Turns a picked or dropped file into a room picture. A still picture shrinks to the compression size; an animated one or a vector drawing is kept as it is. |
| `roomPictures.js` | A room's pictures in the left panel: adding, reordering, deleting, and the one picture shown on the TV, which comes down when its room, its picture or its scene goes. |
| `moduleText.js` | Parsing a published module's text into locations, storing them, and carrying them through a backup. |
| `moduleTextPanel.js` | The panel that takes a module file, and the room name field as a searchable dropdown over what it found. |
| `pdfLayout.js` | Turning a PDF's scattered text fragments back into reading order. It also lays the text out a second time for the stat block finder, each line tagged with its font and a band started at each wide stat block box. Pure functions, unit-tested, no dependencies. |
| `pdfExtract.js` | Runs pdf.js in an isolated child process, on bytes or on a path it reads itself. No `<script>` tag: this one never loads in the browser. |
| `confirmDialog.js` | The app's own dialogs: a yes/no question, and a one-button message for errors. The only sanctioned pair, because a native `confirm()` or `alert()` breaks the page's focus. One shows at a time; a second waits its turn rather than replacing it, so no question is dropped unanswered. It also owns the toast stack above the toolbar, which every toast in the app is built into. |
| `icons.js` | The icons every window shares: one cross for a close, one trash for a destructive button, and the rest of the window set. |
| `i18nPlan.js` | The interface language's pure kernel: looks a string up in the dictionary with the English as the fallback, fills `{name}` values into it, and picks the Russian plural form for a count. No DOM, so it is unit-tested. |
| `ru.js` | The Russian dictionary, keyed by the English text exactly as the screen shows it, plus a second table for counts. Data only. |
| `i18n.js` | The interface language. Picks it once at start (the DM's stored choice, else the computer's language) and exposes `t()` for text the code builds. In Russian it swaps every piece of English on the DM's screen it finds in the dictionary, and watches for text added later; the DM's own text is marked and skipped. In English it does nothing. Also builds the English / Русский switch in the About block. |
| `about.js` | The About block at the foot of Settings: the app mark, the version number, the repo address and What's new, with the language switch above it. Builds its own markup rather than adding any to `index.html`. DM only. |
| `musicPlan.js` | The music library's pure kernel: it reads a pasted YouTube link into a video or playlist id, reads a track's id and display name back out of its filename, filters the track list, and gives the equal-power level of a fade at a given phase, and says whether the bundled downloader is older than the newest release. No DOM and no Electron, so it is unit-tested. |
| `music.js` | The dock's Music pane: a player with play and pause, the track, its state and the volume, over a list of whatever audio files sit in the app's music folder, plays one on a click and crossfades to the next, pauses without losing its position, carries the volume and the filter, deletes a track, and opens the Add music panel. The folder is the whole library, so there is no database behind it. DM only. |
| `musicGroups.js` | The Music pane's groups: a group is a name a track carries, stored in the app's settings by file name, so the files never move. It builds each group's heading with its rename field, count and delete, folds a group shut, and files a track dragged onto a heading. The pure grouping is `sceneGroups.js`'s, shared with the scene library. DM only. |
| `musicDownload.js` | The Add from YouTube window: it reads a pasted YouTube video or playlist link as it is pasted, lists what is behind it with the tracks already on disk marked, and downloads the ones ticked one at a time. How far a queue has got is drawn as a bar under the Music pane's player, and a queue still running survives the panel being closed and reopened. It also carries the button that updates the downloader, which appears only when a newer release of it exists. Split out of `music.js` and joined to it by three functions rather than a shared variable. DM only. |
| `soundList.js` | The soundboard's thirty built-in sounds in six groups of five: each one's file in `assets/sounds/`, and its English name. Data only. |
| `soundboard.js` | The dock's Sounds pane: its volume slider, then all thirty sounds as tiles two to a row under their group's name. A left click plays one more copy of a sound over the ones still sounding, a right click stops the newest copy, and its own volume slider sets the level. The files are decoded once into Web Audio buffers, so any number of copies can overlap. DM only. |
| `combatPlan.js` | The arithmetic behind the fight table: adding up the HP line the DM types after the stat block's max HP, whether a creature is bloodied or down, initiative order, ability modifiers.
