# Architecture - the module map

Split out of [ARCHITECTURE.md](../ARCHITECTURE.md). One row per file: what it owns, in plain
language, present tense. The terse version every session carries is in
[CLAUDE.md](../../CLAUDE.md)'s own module map; this is the one read on demand.

| File | What it does |
|------|--------------|
| `index.html` | The entry point and page markup, and nothing else. The JavaScript here is just wiring: grab the canvases, start PixiJS, call each module's `init`, connect the lifecycle events. The styling is nine `<link>` tags. It was once a ~2400-line script plus a ~1370-line stylesheet, and a guard hook keeps either from creeping back. |
| `src/css/*.css` | All of the app's styling, split by the part of the screen it dresses: `base.css` (page reset, the floating-panel surface every control shares, canvas layers, player mode), then `controlPanel.css`, `toolbar.css`, `roomCard.css`, `playerPane.css`, `legend.css`, `sceneManager.css`, `about.css`, `combat.css`, `dock.css`, `notesWindow.css`, `worldMap.css`, `overlays.css`. They load in that order and it matters, because CSS is one shared cascade. |
| `cursorPack.js` | Evermist's own pointers. Each kind (arrow, clickable, text, draw, move, grab, holding, rotate, the four resize arrows, the divider) is drawn on a canvas at normal and double resolution and written on the page as a CSS variable, so every cursor rule in the stylesheets and every cursor the code sets shows the pack's picture with the system cursor only as a fallback. The splash and the two-map shell load it on its own. |
| `companionLogic.js` | The crystal companion's pure kernel: which mood it is in (following, happy over a button, angry at six fast clicks on empty map, dizzy at a shake, asleep after 25 still seconds, working while busy), where it hovers beside the pointer and the hop away from a window's edge, the shape its twelve outline points morph to, and the springs that move it. Reduced motion keeps the resting shape. Unit-tested. |
| `companionSwitch.js` | Settings' "Crystal companion" switch. Kept in `localStorage` only when off, so an older release reads nothing. |
| `companion.js` | The crystal companion on screen: one small canvas above everything that follows the pointer, drawn as the morphing core with a glowing orb. It runs only while the pointer is inside its own document, so a two-map column or a Player half shows the one crystal and its parent shows none. It reads the pointer kind off the computed cursor, works while a map or a PDF loads, hides while the cursor is hidden, and passes the switch on to every Player window and column. |
| `renderer.js` | The PixiJS/WebGL wrapper: the drawing context, the layers everything else hangs off, the map sprite and the texture pool behind it. Each fog pass has its own file beside this one. |
| `playerFogPass.js` | The Player's fog drawn as one pass over the whole window, shaders and all. Covering the window rather than the map is what leaves no edge for a seam to sit on. |
| `playerFogShader.js` | The Player's fog shaders, as source. Data only. |
| `playerFogTrans.js` | A fog change on the TV: the order texture the shader reads, changes that overlap in time each on their own clock, and the outgoing mask until the last has run. |
| `fogTransitionPlan.js` | The pure order maths of a TV fog change: the changed pixels, their noise ranked over the region, and which pixels a new change takes from one still moving: every changed pixel, never a pixel only in its ring. Unit-tested. |
| `dmFogLayer.js` | The DM's fog, which is a different thing entirely: map-sized sprites, the crossfade between the fog before an edit and after it, and the drifting cloud texture masked to wherever fog is opaque. |
| `render.js` | The render loop. Each frame it decides which layers actually changed and redraws only those, keeps the canvases sized to the window, and paints the cursor and polygon-selection overlay. |
| `state.js` | Shared values that several files need. Loaded first so they exist before anything reads them. |
| `fog.js` | The fog itself: the canvases that store what is hidden, the blur pipeline that softens them, and the reveal/hide logic. |
| `fogAnim.js` | Four loops, each ticking against the clock: clouds drifting and morphing, a reveal or shroud fading in, the fog closing over a scene switch and opening again, and the fog colour easing from one scene's to the next. A loop that stalls shows the players a frozen picture, so each one owns its own frame handle and can be stopped on its own. |
| `fogClouds.js` | The soft moving texture that stops the fog reading as a flat fill. One window builds the sixteen frames and every other window copies them, because building four sets at once freezes all of them for seconds. |
| `fogControls.js` | The fog's door-size inputs behind Map settings, remembered between sittings. It reads and writes fog settings; it draws nothing. |
| `fogGeometry.js` | The pure fog math: polygon insetting, rounded paths, cone vertices, tint-colour derivation, animation timing. Plain functions in, values out, no drawing. Unit-tested. |
| `fogTheme.js` | The fog theme on a live window: the DM's pick (colour, tint and motion together, sent to the TV, held in Manual), a map's restore, and what the Player does with the theme it is sent, so the effects switch on once the colour has eased. |
| `themes/fogThemes.js` | The fog themes' registry: the list the dropdown, the TV's shaders and a saved map read, and the pure `fogThemeNormalize` that turns any stored id into a known one. Unit-tested. |
| `themes/default.js` | The Default fog theme: its colour, tint, motion and its own shader branch. One file per theme; `blood.js`, `toxic.js`, `ice.js` and `fire.js` sit beside it. |
| `fogColor.js` | The colour arithmetic behind the fog: a theme's colour into the solid fill and the tint that glows over it, the halfway step between two of them for a scene change, and the reader for the older look settings a saved scene still carries. Plain functions in, values out. Unit-tested. |
| `doorGeometry.js` | The pure door math: notch placement and corners, cell snapping, which wall a point is near, door placement from a floor plan, shared-wall detection, and the remap that keeps a door on its map point when the outline changes. Unit-tested. |
| `shapeDetail.js` | Carries a room's per-vertex and per-wall detail across a repair: it flattens each curve for the clipping library, then rebuilds the surviving stretches as exact cubics and puts each corner radius and each door back on the wall that now holds it. Unit-tested. |
| `lightGeometry.js` | Reads a floor plan's lights into map pixels, and works out the polygon each starts as: its room, clipped by its radius, or a circle when no room holds it. Pure geometry, unit-tested. |
| `vttPlan.js` | Turns a Universal VTT floor plan's wall segments into room polygons, and reports where its openings sit. Pure geometry, no dependencies, unit-tested. |
| `vttHoles.js` | The free-standing buildings a floor-plan room encloses, given to that room as holes, so revealing a hall leaves the vault inside it hidden. Pure, unit-tested. |
| `roomOps.js` | Reshapes rooms already on the map: joins the ones a drawn shape overlaps into one, trims a drawn shape out of them, splits them along a drawn shape's edge (the part inside becomes a room of its own), and cuts one room into two along a clicked path. Wraps the vendored `polygon-clipping` library and answers with vertex lists or a refusal reason, never a throw. Unit-tested. |
| `floorPlan.js` | The app side of that: finding the plan beside the map, the offer notice, setting Grid Size from the plan at import, and drawing the rooms and their doorways. |
| `tools.js` | Which tool the DM is holding, the state every tool shares, and the table a click is dispatched through. Each tool is a row in that table and a file of its own, so a new one is added without touching the others. The cone is drawn apex-first - press at the point of origin, drag towards where it points - and commits as an ordinary polygon with a shallow arc on its far edge, so nothing downstream knows a cone from any other shape. |
| `shapeCommit.js` | What happens to a shape once it is drawn: it becomes a room, an effect, or a repair of one already there. Join, Trim and Cut all end here, and so does every refusal the DM sees. |
| `toolPoly.js` | The Polygon tool: one vertex per click, closing either by clicking the first vertex again or by crossing its own line. |
| `repairKeys.js` | What a drawn shape does to the rooms it touches: Shift merges it in, Alt cuts it out, Ctrl splits them, and the bar's repair icon arms the same with no key held. Feeds the outline, the tag by the pointer and the icon, and tells the shell which key a column holds. |
| `presetGeometry.js` | The pure preset math: the sizes each shape offers in feet (one grid square a step, from each shape's smallest to its largest), the outline a size makes at the grid's scale, the cursor label, a size's name in feet and squares, and the step through a size list, which stops at both ends. Unit-tested. |
| `toolPreset.js` | Effect presets: the outline and label that follow the cursor, the wheel and [ ] that step sizes, and placing one with a click or an aiming drag. The size field is `effectsRow.js`'s. |
| `toolShapes.js` | The three tools drawn by dragging: rectangle, circle and cone. Each starts on the press and commits what it has on release. |
| `toolBrush.js` | The fog brush. Strokes queue while the pointer moves and land in one pass, so painting stays smooth on a big map. |
| `toolDoor.js` | The Door tool: which wall a click belongs to, where along it the door sits, the notch that opens in the fog there, and the ghost of that door under the pointer before the click. |
| `toolCut.js` | The Cut tool: a free path drawn across a shape, and the two pieces it leaves. |
| `shapeMarkers.js` | Draws one corner (square at object level, circle in edit mode, an optional coloured ring or stroke) and one hole's hatch fill. Read by shapeSelect.js, shapeBox.js and toolPreview.js alike, so it belongs to none of them. |
| `toolPreview.js` | The outline a tool shows while the DM is still drawing, before anything is committed. |
| `shapeHit.js` | What the cursor is over: whether a point is inside a room, how far it is from a wall, and where along that wall it lands. A bent wall is measured against its curve. Pure. |
| `shapeSelect.js` | The Select tool: what is picked, and every edit made by hand on the map. It holds the levels the way Figma does - one click picks a shape as a whole object and draws its bounding box, a double-click enters edit mode and puts its vertices, walls and holes in reach, and a Ctrl+click on a shape not yet open does the same in one press. A hole is picked by clicking its empty middle, takes a box of its own, and opens its corners on one more double-click; Escape climbs back one level per press. Only the live level answers the mouse. A hole moves as one ring and stops where it would leave its room. Also draws every room and effect: a wash carrying its fog state, a soft inner edge, and a line that goes gold when held and white while editing. |
| `openLine.js` | What the room editor draws for a picked road: an open line has no fill and no closing wall, so its chrome is the line gone gold and, in edit mode, its corners and the selected corner's curve handles. The handle markers are shared with `drawPolyOutline`. |
| `cornerGeometry.js` | The pure corner-rounding math: where a corner's rounding circle sits, which way a drag along it grows the radius, and how far each corner can round. Unit-tested. |
| `cornerRound.js` | The rounding circles on a picked shape's corners, the drag that rounds one corner or all of them, its label, and the number field a double-click opens beside a circle. |
| `shapeBox.js` | The bounding box a picked shape wears, and the rotate and scale its four corner handles drive. A corner scales against the opposite corner; the ring just outside it rotates around the box centre. Shift holds proportion and snaps rotation to 15 degrees. A picked hole gets the same box, and stops where it would leave its room. |
| `shapeClipboard.js` | Copy, cut, paste and duplicate for rooms, effects and holes, on Figma's Ctrl+C, Ctrl+X, Ctrl+V and Ctrl+D, and the copy an Alt+drag moves. Cut is a copy and a delete, one undo step; an Alt+drag makes its copy on the drag's first movement and spends only the drag's own undo step. A paste centres the shape on the pointer and a duplicate lands one grid square across. The copy keeps its name, its description and its fog state. The clipboard outlives a scene switch and remembers which list it came from, so an effect pasted in Rooms mode still lands among the effects. A copied hole pastes as a hole into whichever shape sits under the pointer. |
| `input.js` | The DM's mouse and keyboard: painting with the tools, keyboard shortcuts, the legend toggle. Files dropped on the window are `dragDrop.js`'s. |
| `undo.js` | Undo/redo history for fog edits. |
| `effects.js` | Map effects - fire and acid. Each is a polygon carrying a material name, drawn under the fog on both screens: a burning border plus whatever the material adds inside it. Rendered by a fragment shader over the polygon's own distance field, in two PixiJS meshes per effect, both blended normally so the DM and the TV paint it alike. Owns the `effects` array's model and the meshes that draw it; the passes themselves are `effectShader.js`'s and their numbers `effectMaterials.js`'s. (The relight of the map grid inside a zone lives in `grid.js`.) |
| `effectMaterials.js` | What an effect is made of. A record per material carries the colours it burns through, how warm the hottest part reads, the grid colour inside it, and its look: the amount of every term the shader can draw, 0 for a term it does not use. |
| `effectShader.js` | The two passes an effect is drawn with: one that paints light - the border, toon flames, a pool and its bubbles, sparks, a glow past the edge - and one over it that takes light away, for smoke, steam and char. Every colour and amount arrives from the material. |
| `weatherPlan.js` | The weather's numbers: the six presets, how hard rain or snow falls over a few minutes, how puddles and settled snow follow, the 8-second fade between two presets and a saved id read back (an unknown one is No weather). Plain functions in, values out. Unit-tested. |
| `timeOfDayPlan.js` | Time of day's numbers: None, Day, Dusk and Night, each a fixed filter in linear light ported from the agreed prototype, the lamp mask Day reads, the weights an 8-second fade blends, and a saved id read back and written (unknown is None, None is no field). Plain functions in, values out. Unit-tested. |
| `weatherShader.js` | The one fragment shader behind every preset: rain, snow, cloud shadow and sunbeams, puddles, settled snow, heavy patches, lightning and the rare gust, with the rooms cut out. Data only. |
| `timeOfDay.js` | Time of day on a live window: the pick and its fade, the rooms' blurred glow and the lamp mask as textures built once per map or room change, and on the DM's animated map a CSS filter on the video for Day. |
| `weather.js` | Weather over a map, on the DM's screen at a third of its strength and on the TV at full. One full-screen mesh between the map and the fog, a second one fading the old preset out, a mask of every room so nothing falls indoors, and the push of the preset and that mask to the TV or a column's half. With No weather the meshes are off. |
| `effectShaderKinds.js` | The one-pass shaders of the effects that are not flames: Area (a bezel of edge lines, crawling ticks and glyphs) and Difficult terrain (heaving relief under crawling shadow pools). |
| `grid.js` | The grid overlay: squares or hexes, size/offset/colour, a solid, dashed or dotted line style (`gridDashPattern`, `normalizeGridLineStyle`; each line starts on a crossing so dashes hold still while panning), and line width that scales with zoom. Also the one place a grid change is committed from - redraw, push to the Player, save onto the scene - and what grid a freshly imported map starts with. Relights the grid in ember inside each effect zone (`drawEffectGridGlow`), because the map grid draws on a canvas above the effect layer. |
| `gridCalibrate.js` | Fitting the grid to a map that already has one drawn on it, without typing numbers. Armed from the Fit icon in Scene control, which puts the dock's pane away so the map is clear; leaving hands it back. **The DM drags the shape the grid is made of.** For a square grid that is a box from one intersection in the map art to another several cells away, forced square because a cell is, which makes the two axes one measurement and lets a map showing only its vertical lines be enough. For a hex grid it is one big hex dragged from a corner to the opposite corner, snapped to one of the six corner directions because corners are what the map art draws, with the grid's hexes drawn inside it. Its diagonal crosses n hexes, each twice the circumradius with a shared wall of one between neighbours, so it is (3n - 1) circumradii; an odd n centres the big hex on a cell and lands all six corners on the grid, and an even one lands only the two corners pressed. The DM's grid is hidden for the length of the gesture, and the square and the big hex each draw their own cells. The cell count is guessed from the size already set and corrected with a stepper floating beside the shape, so the cell is the drag divided by what that count spans; the stepper sits clear of the magnifier; a drag too small to fit one cell is refused rather than clamped. Once drawn the shape stays live: drag its middle to slide the phase with the cell size held, or its far handle to resize with the count held. Past the box, a square grid also offers a handle on any intersection that re-solves the cell size by least squares so the grid lands there, which takes out the error a short measurement multiplies over a long map. A magnifier shows the map at four times the on-screen scale, and an animated map is held on one frame for the length of the gesture. Owlbear Rodeo, Roll20 and Foundry all size from a fixed multi-cell square and then correct at a distance; this is that shape with a count the DM can raise. |
| `scenes.js` | Auto-save loop, fog-load helpers, and the error-recovery path above the database layer. |
| `trashPlan.js` | The pure rules of Trash: the days a map has left, which entries are due, and the road ends a map held, put back on Restore when nothing took them since. |
| `sceneTrash.js` | Trash on this computer. A deleted map's whole record waits 30 days in its own database, `evermist-trash`, and an animated map's file in `userData/trash`. The entry is written before the map leaves the library, so a crash leaves a duplicate, never a loss. Restore puts the record, the file, the place on the list and the road ends back; the start-up reconcile drops an entry whose map is in the library again and purges what is due. A deleted music track gets an entry in the same database (store `tracks`) and its file moves to `userData/trash/music`; Restore puts it back under its name, or " (2)" when that is taken. |
| `sceneDelete.js` | Deleting a scene, and taking it back. The list loses the scene at once, and once the undo toast runs out the map moves to Trash (`sceneTrash.js`). Deleting the scene on screen also empties the app and moves it to another one, and the TV waits on its fog screen until the DM opens a scene or sends. |
| `sceneList.js` | The list of scenes the app holds, whatever shows it: loaded at startup with the last scene reopened, its thumbnails kept in step, the open scene's name in the dock, and the counter that drops a stale scene switch. The Scene library and the world map both read it. |
| `mapImport.js` | Turning files the DM picks or drops into scenes: which kinds are accepted, how a whole selection is taken in one at a time, how a second import waits for the first to finish, and where an animated map is written. Problems are collected and reported once at the end, so a long import never waits on a click. |
| `sceneSwitch.js` | `switchScene`: the fog closing over the outgoing map, the store read, the decode, and the fog reopening on the new one. Every path into a loaded map goes through it. |
| `sceneGroups.js` | Groups in the scene library. A group is a name a scene carries, so the scene's own `group` field is the only record of what is filed where; this file keeps the order the headings appear in, which ones are collapsed, and a heading made before anything was dragged into it. |
| `editStamps.js` | The time each part of a scene last changed: its name, grid, map, fog, notes, fog settings and lights, and for each room its shape, its notes and its revealed state. A save compares what is stored with what it writes and stamps what differs. Also the uid that identifies a room or effect on every machine. Unit-tested. |
| `transferPlan.js` | The rules an import follows for a scene both machines hold: each part goes to the copy edited later, rooms and effects match by uid, a room deleted on one machine goes on the other unless it was edited later there. The same for places, roads and the backdrop. Unit-tested. |
| `sceneStore.js` | Saving and loading scenes to the browser's local database (IndexedDB). Every save stamps the parts that changed (`editStamps.js`); `putScene` writes a record as it is, for an import. Changing one field of a scene the app is not currently showing goes through `updateScene`, which reads and writes in one transaction so an autosave cannot land between the two and lose a fog reveal. |
| `mapLoader.js` | Loading a map image into the app and driving the progress bar, including the batch label a multi-map import puts on it. Shared by scene-switching and backup restore. |
| `mapConvert.js` | Asking whether to shrink an oversized animated map at import, and re-encoding it if the answer is yes. Pure box-fitting maths plus the recorder that drives it. |
| `viewport.js` | Pan, zoom, fitting a map to the screen, and the camera arithmetic every push to the Player carries. |
| `mapTurn.js` | The seat (Seat alignment): the DM's map turned 0°, 90°, 180° or 270° so the laptop faces the way the table does from the DM's chair. Every canvas over the map turns together, so nothing drawn can slide off the map; the few places that meet a mouse position or place a panel convert through here. The TV never sees it. |
| `ping.js` | The ping: a gold ring with ticks, ripples and sparks at a map point for about two and a half seconds, drawn in the DM window and on the TV alike. It is sized to the window rather than the map and stored nowhere. |
| `lights.js` | A scene's lights, which are polygons in a list of their own. It seeds them from the floor plan on request, draws a faint warm line round the lit areas under the fog on both screens, and sends the outlines to the Player. |
| `playerWindow.js` | The DM's side of the Player window: opening it, keeping a warm one ready so the next press is instant, and deciding what is sent to it and when. |
| `fogPreview.js` | The hover preview of Reveal all and Hide all: the DM's fog layer hidden or covered, inside a green or purple frame that ends at the dock. Render-only: no fog state, no undo, nothing to the Player. |
| `playersView.js` | The players' view: holding H shows the DM's own map with the fog at full strength, the room outlines hidden and a blue frame around it. |
| `minimap.js` | The DM's live preview of the Player camera in the bottom-left corner, and the remote control that drives it. |
| `tvPick.js` | Which screen is the TV, decided from the display list and the pick the DM made last time. No screen of its own; unit-tested. |
| `tvFit.js` | Turn: a scene's own turn of the TV picture, kept as a step and a quarter-turn. The three tiles and the saved form each reads as; no screen of its own; unit-tested. |
| `tvInch.js` | 1 inch: the zoom that makes one map square 1.1 inches wide on a TV of a given size, from its diagonal and full pixel width; the sizes TV setup offers; which size a TV reports is believable; the per-TV store's key and read. No screen of its own; unit-tested. |
| `tvControl.js` | Show on TV: the control on the minimap that puts the map on the TV. It owns the off, waiting and live states, the pill under the picture, TV setup, the screen question and the help box for a machine with one screen. |
| `tvOneInch.js` | 1 inch: the minimap button that zooms the TV to 1.1-inch squares, TV setup's TV size row (picker, Other's field, where the size came from), and the size kept per TV in `evermist.tvSizes`. |
| `stageWindow.js` | The DM side of the Player screen while two maps are up: opening that window, keeping a warm one ready so the next press is instant, wiring each column to its own half, and closing it. |
| `paneRuntime.js` | The other end of every command the DM shell sends a column. Each message presses the control that column already has, so a column behaves like the DM window it is, and no behaviour is written twice. |
| `panes.js` | Two-column mode, where the DM window's map area splits in two and each half holds a whole second copy of the app running in an `<iframe>` with its chrome hidden. Owns the two frames, which column is selected, the draggable divider, and every command the DM's chrome sends into a column. A column therefore has its own scene, camera, grid, rooms, fog, undo history and Player window with nothing written for it. Also the small piece that runs INSIDE a column: Electron gives a subframe no bridge to the shell, so the column borrows the parent window's. |
| `twoMaps.js` | The Two maps toggle in the dock: into two columns from the open map, and back to one. |
| `stage.js` | The Player window in two-map mode. One window, split where the DM's divider sits, holding a whole Player in each half and painting the chasm between them - a dark band with each floor's fog colour bleeding in, embers drifting up it and a faint seam of light down its centre. One window rather than two because Windows gives one fullscreen window per display, so a pair could never both be fullscreen on the same TV. |
| `video.js` | Animated (video) map support: file loading, DOM compositing, decoding, the frame loop, the freeze watchdog. |
| `videoDiag.js` | A panel that shows how an animated map is actually playing, plus the log file it writes. The counting runs whether or not the panel is open, so a stutter the DM only hears about later is still on record. |
| `display.js` | Detecting the Player screen's real size so the fog and map render at the right resolution. |
| `backup.js` | The export-to-zip feature, and the module text and fights an import adopts. |
| `transferImport.js` | Import: a picked or dropped `.zip` merged into the library scene by scene, with the plan from `transferPlan.js`. It reports what was added, updated, kept and overwritten, opens the world map on what came in, and puts every scene back if the import is stopped. |
| `syncPlan.js` | The sync rules with no screen or network: what goes up, what is new from another computer, which map files the Drive already holds or no longer needs, which pulled changes wait for the open, TV or Two-maps map, the fight table or an open note, the 30-day trash a deleted map goes to, what the first-sync question counts, and which kept map files are past their 30 days. Unit-tested. |
| `syncIndex.js` | What sync knows without reading the library: each record's content hash as last saved here, hashed when saved and reconciled at start, and the deletion records of maps, in a database of its own. Does nothing without a Google client. |
| `syncMerge.js` | The silent merge entry: a record pulled from another computer (a map, a picture, the Campaign's places, roads, party marker and deleted pictures, the backdrop, a stored text) is applied with Import's plan rules and none of what Import does around them (no panes closed, no forced save, no progress bar, no dialog, no scene switch). A change for the open, TV or Two-maps map, the fight table or an open note waits until it is let go, and a pending delete defers all. One record per idle slice, each stretch timed as a `sync:` performance measure. |
| `syncMusicPlan.js` | The music-sync rules with no screen or network: what the music folder gained or lost since the last tick, which tracks to fetch, send or remove, the deletion records and their 30-day trash, the groups the later edit keeps, and the `music` record written and read back. Unit-tested. |
| `syncMusic.js` | The music folder through sync: the tick's music part, run after every map, record and note; this computer's `music` record; tracks in Trash with Restore and Empty now; and the hash a track gets as it lands. |
| `sync.js` | Sync's outbox and inbox on the page: a tick a few seconds after a change, every 30 s, at start, when the network returns and on Sync now. Records and map files go up once, other computers' changes come down, the first sync keeps copies and deletes nothing, and the status line's state is kept here. |
| `syncSettings.js` | Settings' Google Drive line: the status line and one button, Connect or Disconnect. Shown only where sync has a Google client; asks before a computer's first sync, and tells `trashPanel.js` whether the Drive's deleted maps join its list. |
| `trashPanel.js` | Campaign's Trash line, always shown, which opens a pop-out: each map and music track with its days left and Restore, and Empty now, which asks first. While sync is signed in it adds the maps and tracks only the Drive holds. |
| `dragDrop.js` | What happens when files are dropped on the DM window. A floor plan arriving alone is attached to whatever scene is open, which is the case where it got separated from the map it belongs to. A dropped map imports nothing; maps come in through the + button. |
| `toolbar.js` | DM-only UI control wiring: toolbar buttons, sliders, the scene dropdown, Player controls. The Fog tab's own controls live in `fogControls.js`. Also the Rooms/Effects switch, the Merge and Cut out repairs, the material picker, and which tools each mode puts on the bar. The strip above the toolbar changes with both - `input.js`'s `updateContextPanels` owns every visibility decision in it. |
| `shapeMenu.js` | The bar's one chevron list and the Shape list. The Shape button always wears the shape you draw with, and its list holds shapes only, with a check on the current pick and a shape the mode lacks greyed. The world map keeps its own Shape list, with a Repair heading over Merge, Cut out and Split that grey and read "Needs a room" while the map has none. A right-click on the Shape button opens the list too; the repair icon and the size field hand their rows to the same list. |
